# 七、磁盘管理与文件系统

> 服务器上几乎所有问题最终都会变成“磁盘满了”：这一篇讲清磁盘、分区、文件系统怎么组织，怎么挂载，以及空间不够时怎么一步步查下去。

## 1. 学习目标与前置知识

读完本篇应能：

1. 说清磁盘、分区、文件系统三者的层级关系，以及 MBR 与 GPT 两种分区表的取舍。
2. 用 `lsblk`、`df`、`du`、`blkid` 等命令判断“磁盘在哪、分区多大、空间被谁吃了”。
3. 写出正确的 `mount`、`umount` 与 `/etc/fstab` 配置，并用 UUID 避免设备名漂移。
4. 按固定流程排查磁盘空间不足，知道删除文件后空间没释放的原因与处理办法。
5. 独立完成一块新磁盘从识别到挂载、再到写入 fstab 并验证的完整流程。

前置知识：[04-Linux基础命令](04-Linux基础命令.md) 的文件与权限基础、[05-Linux用户和权限](05-Linux用户和权限.md) 的 root 与 sudo、[12-Linux实用操作-压缩与解压](12-Linux实用操作-压缩与解压.md) 的打包思路、[14-文本处理三剑客](14-文本处理三剑客.md) 里 `grep`/`awk` 的过滤能力。

磁盘相关命令几乎都需要 root 权限：读操作普通用户可执行，但 `fdisk`、`mkfs`、`mount`、修改 `/etc/fstab` 必须用 `sudo`。

## 2. 磁盘、分区与文件系统

拿到一块硬盘，系统要先把它“切开”，再在切出来的空间上“铺一层文件系统”，最后“接进目录树”才能用。三层各管一件事：

| 层次 | 是什么 | 常见对象 | 常用工具 |
| --- | --- | --- | --- |
| 磁盘 | 物理设备或虚拟设备 | `/dev/sda`、`/dev/vda`、`/dev/nvme0n1` | `lsblk`、`fdisk -l` |
| 分区 | 磁盘上的连续区段，记录在分区表里 | `/dev/sda1`、`/dev/sda2` | `fdisk`、`parted` |
| 文件系统 | 分区上组织文件的数据结构 | ext4、xfs、btrfs | `mkfs.ext4`、`mkfs.xfs` |
| 挂载点 | 文件系统接入目录树的位置 | `/`、`/data`、`/boot` | `mount`、`/etc/fstab` |

~~~mermaid
flowchart TD
    A[物理磁盘 /dev/sda] --> B[分区表 MBR 或 GPT]
    B --> C[分区 /dev/sda1]
    B --> D[分区 /dev/sda2]
    C --> E[文件系统 ext4]
    D --> F[文件系统 xfs]
    E --> G[mount 到 /boot]
    F --> H[mount 到 /data]
    G --> I[目录树]
    H --> I
~~~

磁盘是硬件，分区是分区表里的一条记录，文件系统是分区内部的数据结构，挂载点只是目录树上的一个位置。四者不是一一对应：一个分区只能有一种文件系统，但一块磁盘可以有多个分区，一个文件系统也可以被挂载到多个挂载点（只读场景）。

### 2.1 MBR 与 GPT 分区表

分区表记录“第几个分区从哪个扇区开始、到哪个扇区结束”。MBR 是几十年前的老格式，GPT 是现代格式。

| 对比项 | MBR | GPT |
| --- | --- | --- |
| 容量上限 | 磁盘最大 2 TiB | 约 9.4 ZiB，实际受硬件限制 |
| 分区数量 | 最多 4 个主分区（可用扩展分区绕开） | 通常 128 个，无主次之分 |
| 是否要求 UEFI | 不要求，传统 BIOS 即可 | 引导系统时通常要求 UEFI（纯数据盘无所谓） |
| 备份分区表 | 无 | 磁盘首尾各存一份，可互相修复 |
| 分区标识 | 32 位分区类型码 | 128 位 GUID，语义更明确 |
| 适用场景 | 老机器、小容量、兼容性优先 | 新装系统、大于 2 TiB 的磁盘 |

用 `parted -l` 或 `fdisk -l` 的输出里 `Disklabel type: gpt` / `dos` 判断当前是哪种；`dos` 就是 MBR。

### 2.2 主分区、扩展分区与逻辑分区

MBR 的分区表只有 4 条记录，于是有了历史遗留概念：

| 名称 | 数量 | 说明 |
| --- | --- | --- |
| 主分区 | 最多 4 个 | 可以直接装系统、直接挂载 |
| 扩展分区 | 最多 1 个 | 占掉一个主分区名额，本身不存数据 |
| 逻辑分区 | 数量较多 | 建立在扩展分区内部，编号从 5 开始 |

所以 `/dev/sda5` 往往出现在 `/dev/sda1`、`/dev/sda2` 之后却“跳跃”编号，就是因为它属于扩展分区。现代做法是用 GPT，分区全部平级、编号连续，不需要再区分主分区和逻辑分区；只有在必须兼容老 BIOS 或老系统时，才会看到扩展分区的写法。

## 3. 查看磁盘与分区

排查磁盘问题要先分清两类命令：`lsblk`、`fdisk -l`、`blkid` 看块设备与分区本身，`df`、`du` 看文件系统里的空间用量。

| 命令 | 看什么 | 输出里要关注的点 |
| --- | --- | --- |
| `lsblk` | 块设备树：磁盘、分区、大小、挂载点 | 有没有分区没挂载（MOUNTPOINTS 为空） |
| `lsblk -f` | 设备树加文件系统类型、UUID、可用空间 | 分区是否已格式化（FSTYPE 为空说明还没 mkfs） |
| `fdisk -l` | 分区表详情：分区表类型、起止扇区、分区类型 | 是 gpt 还是 dos、分区大小是否对齐 |
| `blkid` | 每个设备的 UUID 与文件系统类型 | 写 fstab 时从这里抄 UUID |
| `df -h` | 已挂载文件系统的容量、已用、可用、使用率 | 哪个挂载点使用率接近 100% |
| `df -i` | 已挂载文件系统的 inode 总数与已用 | 空间还剩但 inode 使用率高 |
| `du -sh` | 指定目录占用的总空间 | 这个目录到底占了多少 |
| `du -h --max-depth=1` | 目录下一层各子目录分别占多少 | 逐层缩小范围定位大目录 |

~~~bash
lsblk                                      # 设备树概览
lsblk -f                                   # 顺带看文件系统类型与 UUID
sudo fdisk -l /dev/sda                     # 只看这块磁盘的分区表
sudo blkid /dev/sda1                       # 取某个分区的 UUID
df -h                                      # 各挂载点剩余空间
df -i                                      # inode 使用情况
du -sh /var/log                            # /var/log 总共占多大
du -h --max-depth=1 /var | sort -rh        # /var 下一层目录按大小排序
~~~

`df` 统计的是文件系统层面已分配的空间，`du` 统计的是目录内文件大小之和，口径本来就不同，差几个百分点很正常；相差几十 GB 就必须查原因。

### 3.1 df 与 du 不一致的两个原因

| 原因 | 现象 | 判断方法 |
| --- | --- | --- |
| 文件已删除但仍被进程打开 | `df` 显示已用很高，`du` 逐层加起来却很小 | `lsof +L1` 找到 deleted 状态的句柄 |
| 挂载点被路径遮住 | `df` 把老数据算在根分区，`du` 只能看到新挂载的内容 | 挂载前后对比同一目录的大小 |

第一种情况最常见：进程打开着日志文件，`rm` 只删掉目录项，进程仍持有文件句柄，数据块要等进程关闭文件或退出才释放，所以 `df` 不下降、`du` 也看不到这个文件。

第二种情况是挂载遮蔽：数据先写进普通目录 `/data`，之后把磁盘挂到 `/data`，旧数据被新文件系统盖住。此时根分区的已用空间里仍是那批旧数据，`du /data` 统计的却是新文件系统，两边自然对不上。正确做法是挂载前确认挂载点为空，或先把磁盘挂到临时目录再迁移数据。

## 4. 文件系统类型与 inode

分区只是连续空间，必须格式化出文件系统才能存文件。选哪种文件系统要看容量、并发和是否需要快照。

| 类型 | 特点 | 适用场景 |
| --- | --- | --- |
| ext4 | 成熟稳定，支持日志与在线扩容，最多 1 EiB、单文件最大 16 TiB | 通用默认选择、系统盘、小文件多的目录 |
| xfs | 高并发写入强，并行分配，不能缩小只能扩大 | 大文件、数据库、日志服务器、CentOS 7+ 默认 |
| btrfs | 支持快照、子卷、校验和与在线压缩 | 需要快照回滚、容器存储的实验环境 |

三者的共同点是都是日志式文件系统：写操作先记日志再落盘，掉电后能快速恢复一致性。扩容命令也不同，ext4 用 `resize2fs`，xfs 用 `xfs_growfs`，xfs 不支持缩小。

### 4.1 inode 与 inode 耗尽

inode 是文件系统给每个文件（严格说是每个目录项）分配的元数据记录，存放权限、大小、时间戳和数据块位置，文件名与 inode 号的对应关系存在目录里。

| 现象 | 原因 | 排查与处理 |
| --- | --- | --- |
| `df -h` 还有空间，却报 “No space left on device” | inode 被耗尽，无法创建新文件 | `df -i` 看 IUse% 是否接近 100% |
| 某个目录里有几十万个小文件 | 每个文件占一个 inode | 找出小文件多的目录并清理或归档 |
| 日志按时间切分且从不删除 | 文件数持续增长 | 加清理策略，用 `find -mtime` 定期删旧文件 |

~~~bash
df -i                                  # 看 inode 使用率
find /var/spool -type f | wc -l        # 统计目录内文件数量
find /var/log -name "*.log" -mtime +30 -delete   # 清理 30 天前的旧日志
~~~

inode 总数在 `mkfs` 时就固定了，事后不能增加，所以 inode 用尽只能清理文件或重建文件系统；这也是日志、缓存、邮件队列这类“小文件海”目录要单独分区的理由。

## 5. 挂载管理

Linux 没有盘符，任何文件系统都要“挂”到目录树上才能访问，这个动作就是挂载；挂载点就是被挂上的那个目录。

~~~bash
sudo mount /dev/sdb1 /data              # 把分区挂到 /data
sudo mount -t xfs /dev/sdb1 /data       # 显式指定文件系统类型
sudo mount -o ro /dev/sdb1 /data        # 只读挂载，排查坏盘时常用
sudo umount /data                       # 按挂载点卸载
sudo umount /dev/sdb1                   # 按设备卸载
mount | column -t                       # 查看当前已挂载的文件系统
~~~

`umount` 报 “target is busy”，说明有进程正在使用该目录：用 `lsof +D /data` 或 `fuser -mv /data` 找出占用进程，退出后再卸载；实在退不掉可以 `umount -l` 做延迟卸载，但不建议在生产环境随手使用。

### 5.1 /etc/fstab 六个字段

`mount` 只在本次开机有效，重启就没了；要开机自动挂载必须写进 `/etc/fstab`。每行六个字段，用空格或 Tab 分隔。

| 字段 | 名称 | 含义 | 示例 |
| --- | --- | --- | --- |
| 1 | 设备 | 要挂载的设备，推荐写 `UUID=...` | `UUID=abc123` |
| 2 | 挂载点 | 挂到目录树的哪个位置 | `/data` |
| 3 | 文件系统类型 | ext4、xfs、swap 等 | `xfs` |
| 4 | 挂载选项 | 逗号分隔的选项集合 | `defaults,noatime` |
| 5 | dump | 是否被 dump 备份，0 表示不备份 | `0` |
| 6 | fsck 顺序 | 开机自检顺序，0 表示不检查 | `0` |

典型两行长这样：

~~~conf
# <设备>              <挂载点>  <类型>  <选项>            <dump> <fsck>
UUID=7f3a-2b91-4c0d   /data     xfs     defaults,noatime  0      0
UUID=9c21-5e77-8a30   /backup   ext4    defaults,nofail   0      0
~~~

### 5.2 为什么用 UUID 而不是设备名

设备名由内核按识别顺序分配，加一块盘、换一个插槽、虚拟化平台调整控制器，`/dev/sdb` 都可能变成 `/dev/sdc`。如果 fstab 里写的是 `/dev/sdb1`，开机时挂载的可能是完全不相干的盘，轻则挂不上，重则把数据写到别的文件系统上。UUID 在 `mkfs` 时生成，跟着文件系统走，不随插槽变化。

~~~bash
sudo blkid /dev/sdb1                    # 取 UUID，也可以看 lsblk -f
sudo lsblk -f                           # 一次性列出全部设备的 UUID 与类型
~~~

### 5.3 常用挂载选项

| 选项 | 作用 | 使用建议 |
| --- | --- | --- |
| `defaults` | 等价于 rw,suid,dev,exec,auto,nouser,async | 绝大多数分区的起点 |
| `noatime` | 读文件不更新访问时间 | 减少写放大，数据库和日志盘建议加 |
| `nofail` | 设备不存在时也允许开机继续 | 移动硬盘、云盘、可选数据盘必须加 |
| `ro` | 只读挂载 | 排查故障或保护数据时用 |
| `noexec` | 禁止在该分区执行程序 | `/tmp`、上传目录的安全加固 |

`nofail` 尤其重要：没有它，一块被摘掉的数据盘就会让系统卡在开机自检，进不了系统。

### 5.4 验证与应急处理

改完 fstab 不要直接重启，先用 `mount -a` 让它按 fstab 重新挂载一遍，没有报错才算配置正确；再配合 `systemctl daemon-reload` 让 systemd 读取新的挂载配置。

~~~bash
sudo mount -a                           # 按 fstab 挂载一遍，验证语法与设备
findmnt --verify                        # 检查 fstab 与当前挂载表是否一致
~~~

~~~mermaid
flowchart TD
    A[改完 /etc/fstab] --> B[mount -a 验证]
    B -->|无报错| C[df -h 确认挂载点与容量]
    B -->|报错| D[按提示修正 或先注释掉该行]
    D --> B
    C --> E[重启前确认还有一个可用的 root 终端]
~~~

万一 fstab 写错导致系统起不来，处理步骤是：重启进入 GRUB 菜单，在内核行末尾加 `rd.break` 或 `init=/bin/bash` 进入救援环境；把根文件系统重新挂成可写（`mount -o remount,rw /`）；用 `vi` 打开 `/etc/fstab` 把出错的行前面加 `#` 注释掉；`exit` 或重启，系统正常进入后再修好那一行，然后重新 `mount -a` 验证。

## 6. 磁盘空间不足排查流程

告警响起时的固定套路是：先定位分区，再逐层找目录，最后确认有没有“看不见的占用者”。

~~~mermaid
flowchart TD
    A[收到磁盘告警] --> B[df -h 找出使用率高的分区]
    B --> C[du -h --max-depth=1 逐层往下找大目录]
    C --> D{du 与 df 差得多吗}
    D -->|差得多| E[lsof +L1 找已删除但仍被占用的文件]
    D -->|差得不多| F[确认是真实数据增长]
    E --> G[重启对应服务 或 truncate -s 0 清空句柄文件]
    F --> H[清理旧数据 归档 或扩容]
    G --> H
    H --> I[再次 df -h 验证空间已下降 加监控]
~~~

~~~bash
df -h                                             # 第一步：哪个分区满了
du -h --max-depth=1 /var | sort -rh | head        # 第二步：逐层缩小范围
du -ah /var | sort -rh | head -20                 # 直接列出最大的 20 个条目
sudo lsof +L1                                     # 第三步：找出已删除但仍被打开的文件
sudo lsof /var/log/app.log                        # 看是哪个进程占着某个文件
~~~

`lsof +L1` 的输出里 `LINK` 列的 `L1` 表示链接数为 1、文件已不可见，`SIZE` 列是它还占用的空间，第一列就是进程名与 PID。确认后有两种处理方式：

~~~bash
sudo truncate -s 0 /var/log/app.log     # 把文件截断为 0 字节，句柄不变，空间立即释放
sudo kill -USR1 $(pidof rsyslogd)       # 信号触发日志程序重新打开文件，日志轮替更规范
~~~

为什么 `rm` 正在被写入的日志不释放空间？因为文件在 Linux 里由 inode 和数据块构成，进程通过文件描述符持有 inode，目录项只是指向 inode 的一个名字。`rm` 删除的只是目录项，inode 引用计数没有归零，内核仍然认为文件在被使用，数据块不能回收，磁盘用量自然不降。只有持有句柄的进程关闭文件或退出，空间才会释放；用 `truncate -s 0` 能在不中断进程的前提下把数据块交还给文件系统。

清理与扩容的选择：日志类数据优先清理或归档，业务数据要评估能否迁移到新盘，根分区持续增长则要扩容 LVM 或云盘。清理后务必再跑一次 `df -h` 确认数字确实下降，只看“命令执行成功”不算完成。

## 7. 新增磁盘完整流程

把一块新盘变成可用目录，固定六步：识别、分区、格式化、挂载、写入 fstab、验证。

| 步骤 | 命令 | 说明 |
| --- | --- | --- |
| 1 识别 | `lsblk`、`lsblk -f` | 确认新盘设备名（如 `/dev/sdb`）与容量，别选错盘 |
| 2 分区 | `sudo fdisk /dev/sdb` 或 `sudo parted /dev/sdb` | fdisk 交互式，n 新建、p 查看、w 保存；parted 适合大容量 GPT |
| 3 格式化 | `sudo mkfs.ext4 /dev/sdb1` 或 `sudo mkfs.xfs /dev/sdb1` | 会清空该分区数据，必须先核对设备名 |
| 4 挂载 | `sudo mkdir -p /data`、`sudo mount /dev/sdb1 /data` | 挂载点必须是空目录，否则内容会被遮住 |
| 5 写 fstab | `blkid` 取 UUID 后编辑 `/etc/fstab` | 用 UUID，数据盘加 `nofail` |
| 6 验证 | `sudo mount -a`、`df -h`、`lsblk -f` | 确认挂载成功且能读写，再重启一次复核 |

~~~bash
lsblk                                     # 识别新盘：本例为 /dev/sdb，无分区无挂载
sudo fdisk /dev/sdb                       # n 新建分区，默认起点与全部容量，p 查看，w 写入
sudo mkfs.xfs /dev/sdb1                   # 格式化，ext4 则换成 sudo mkfs.ext4 /dev/sdb1
sudo mkdir -p /data                       # 创建挂载点
sudo mount /dev/sdb1 /data                # 临时挂载
sudo blkid /dev/sdb1                      # 取 UUID
echo "UUID=7f3a-2b91-4c0d /data xfs defaults,nofail 0 0" | sudo tee -a /etc/fstab
sudo mount -a && df -h /data              # 验证 fstab 配置并确认容量
sudo chown -R app:app /data               # 按需把目录交给业务用户
~~~

fdisk 保存分区表后内核可能还读不到新分区，用 `partprobe /dev/sdb` 或 `partx -a /dev/sdb` 让内核重新读取；格式化前一定用 `lsblk` 再确认一次设备名，`mkfs` 写错盘只留下一句“成功”，数据却没了。

## 8. 小白易错点

1. 先往挂载点目录写数据再挂载新盘：新文件系统把老数据盖住，`du /data` 看不到，根分区空间却一直不降。挂载点必须是空目录，老数据先在临时目录挂好再迁移。
2. 以为 `df` 与 `du` 必须一致：逐个目录加总永远少一截就怀疑命令坏了。两者统计口径不同，差距大时用 `lsof +L1` 查已删除但仍被打开的文件。
3. fstab 里写设备名 `/dev/sdb1`：加一块盘或换插槽后重启，挂载失败甚至把数据写进别的盘。改用 `UUID=...`。
4. `mkfs` 写错设备名：直接清空另一块盘的元数据，数据无法找回。格式化前用 `lsblk` 核对设备名与容量，再确认一次。
5. 改完 fstab 不验证就重启：系统卡在开机阶段进不去。改完先 `mount -a`，无报错再重启。
6. 数据盘忘记写 `nofail`：这块盘被摘掉或云盘未挂载时，系统卡在自检无法开机。非系统盘一律加 `nofail`。
7. `umount` 报 target is busy 就强行关机或热拔：文件系统损坏、数据丢失。用 `lsof +D` 或 `fuser -mv` 找占用进程后正常卸载。
8. 用 `rm` 删正在写入的日志：`df` 数字纹丝不动，以为删除没生效。用 `truncate -s 0`，或让进程重新打开文件。
9. `df -h` 明明还有空间却报 “No space left on device”：inode 用尽。用 `df -i` 确认，再清理小文件。
10. 对 xfs 用 `resize2fs`：命令不存在，或误以为能缩小分区。ext4 才用 `resize2fs`，xfs 扩容用 `xfs_growfs`，且 xfs 不能缩小。
11. 分区表保存后直接格式化：内核还没读到新分区，提示设备不存在。执行 `partprobe /dev/sdb` 让内核重新读取。
12. 云盘控制台扩容后 `df -h` 没变：只扩了块设备，分区和文件系统还没扩。依次 `growpart`、`resize2fs` 或 `xfs_growfs`。
13. 把挂载点选成非空目录（比如 `/root`、`/var/log`）：原内容被遮蔽，甚至影响登录。挂载点用专门创建的空目录。
14. 只删文件不清理句柄就宣布故障解决：过几分钟告警再次触发。清理后必须再跑 `df -h` 验证，并补上磁盘监控。
15. `lsblk` 看得到设备但 `df` 里没有：分区没格式化或没挂载。用 `lsblk -f` 看 FSTYPE 与 MOUNTPOINTS 判断卡在哪一步。

## 11. 本篇总结

1. 磁盘、分区、文件系统、挂载点四层各司其职，磁盘是硬件，分区表记录切分方式，文件系统决定怎么存文件，挂载点把它接进目录树。
2. MBR 上限 2 TiB、最多 4 个主分区，GPT 容量大、分区多、首尾有备份分区表；新系统优先 GPT。
3. 主分区、扩展分区、逻辑分区是 MBR 的历史遗留，GPT 下分区全部平级。
4. `lsblk`、`lsblk -f`、`fdisk -l`、`blkid` 看设备与分区，`df -h`、`df -i`、`du -sh`、`du -h --max-depth=1` 看用量。
5. `df` 与 `du` 口径不同，不一致的常见原因是已删除但被进程打开的文件，以及挂载点被目录遮住。
6. ext4 通用，xfs 适合大文件与高并发且不能缩小，btrfs 支持快照与子卷。
7. inode 记录文件元数据，总数固定；空间有余却写入失败先看 `df -i`。
8. `/etc/fstab` 六个字段是设备、挂载点、类型、选项、dump、fsck 顺序；设备用 UUID，数据盘加 nofail。
9. 改完 fstab 先 `mount -a` 验证；写错导致无法开机时进救援模式把出错行注释掉。
10. 空间不足按“df 找分区 → du 找目录 → lsof 找句柄 → 清理或扩容 → df 复核”五步走，`truncate -s 0` 能立即释放被占用的日志空间。
11. 新增磁盘是“识别、分区、格式化、挂载、写 fstab、验证”的固定流程，每步都要核对设备名。
