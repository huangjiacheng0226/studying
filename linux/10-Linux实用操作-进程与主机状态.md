# 四、Linux 实用操作（五）：进程与主机状态

本篇围绕两件事：一是看懂进程本身，包括进程与程序的区别、PID 与父子关系、前台与后台；二是会用 ps、kill、top、free、df、iostat、sar 观察主机状态。

## 1. 进程基础

程序运行后会被登记为进程，并获得唯一 PID。进程还可能有父进程 PPID。

### 1.1 进程与程序的区别

| 对比项 | 程序 | 进程 |
|---|---|---|
| 存在形式 | 磁盘上的可执行文件，静态 | 内存中正在运行的实例，动态 |
| 数量关系 | 一个程序文件 | 可以同时启动多个进程，例如同一个 jar 启两个实例 |
| 生命周期 | 长期保存在磁盘上 | 随启动、退出而生灭 |
| 占用资源 | 只占磁盘空间 | 占用 PID、内存、CPU、打开的文件句柄 |

### 1.2 PID 与 PPID

- PID 是进程的唯一编号，由内核在进程启动时分配；进程退出后编号会被回收，可能被新进程复用。
- PID 1 是系统初始化进程（systemd），其他进程最终都挂在它下面；父进程先退出时子进程会被 PID 1 收养，所以 PPID 为 1 是正常现象。
- PPID 是父进程的编号，子进程由父进程创建，例如 shell 每执行一条命令就会创建一个子进程。
- 拿到 PID 之后可以继续调查：kill 发信号、lsof -p PID 看打开的文件、ls /proc/PID 看进程信息。

### 1.3 前台与后台进程

| 类型 | 启动方式 | 特点 |
|---|---|---|
| 前台进程 | 直接执行命令 | 占用当前终端，Ctrl+C 中断，Ctrl+Z 暂停 |
| 后台进程 | 命令末尾加 & | 不占用终端，仍然属于当前 shell 的任务 |

~~~bash
sleep 100 &                              # 后台启动
jobs                                     # 查看当前终端的后台任务
fg %1                                    # 把 1 号任务调回前台
bg %1                                    # 让暂停的任务在后台继续
nohup java -jar app.jar > app.log 2>&1 & # 脱离终端运行，日志写入 app.log
~~~

后台进程仍然与终端关联，直接关闭终端会收到 SIGHUP 而被终止；用 nohup 或 setsid 可以让它脱离终端继续运行。

### 1.4 查看进程树

进程之间构成树形结构，查看进程树能一眼看出是谁启动了谁。

| 写法 | 含义 | 适用场景 |
|---|---|---|
| pstree -p | 以树形展示进程，并用括号标注 PID | 快速看清父子关系 |
| ps -ejH | 用 ps 输出进程树 | 机器上没有 pstree 时 |

## 2. ps：查看进程

ps 是进程快照工具，执行一次输出当前时刻的进程列表，两种常用写法：`ps -ef` 偏系统视角，`ps aux` 偏资源视角。

### 2.1 ps -ef：查看全部进程

~~~bash
ps -ef                 # 查看全部进程并显示完整信息
ps -ef | grep tail     # 筛选 tail 相关进程
ps -ef | grep 30001    # 按关键字或 PID 筛选
~~~

grep 自身也会出现在结果中，通常可以忽略。

| 字段 | 含义 |
|---|---|
| UID | 所属用户 ID |
| PID / PPID | 进程 ID / 父进程 ID |
| C | CPU 占用率 |
| STIME | 启动时间 |
| TTY | 所属终端，? 表示非终端启动 |
| TIME | 占用 CPU 的时间 |
| CMD | 启动命令或程序路径 |

### 2.2 ps aux：查看资源占用

~~~bash
ps aux                       # 显示所有用户的进程及资源占用
ps aux --sort=-%mem | head   # 按内存占用从高到低排序
~~~

| 字段 | 含义 |
|---|---|
| USER | 启动进程的用户 |
| PID | 进程 ID |
| %CPU | CPU 占用百分比 |
| %MEM | 物理内存占用百分比 |
| VSZ | 虚拟内存大小，单位 KB |
| RSS | 常驻物理内存大小，单位 KB，比 VSZ 更能反映真实占用 |
| TTY | 所属终端 |
| STAT | 进程状态，取值见 2.4 |
| START | 启动时间 |
| TIME | 累计占用 CPU 的时间 |
| COMMAND | 启动命令 |

### 2.3 过滤自身进程与 pgrep、pkill

`ps -ef | grep 关键字` 会把 grep 自己这条命令也匹配出来，因为它的命令行中含有相同的关键字，所以常用 `grep -v grep` 把它排除。pgrep 与 pkill 更省事：pgrep 直接输出匹配进程的 PID，pkill 可以直接按名字结束进程，省去先查 PID 再 kill 的一步。

~~~bash
ps -ef | grep java | grep -v grep   # 排除 grep 自身
pgrep -af java                      # 按进程名查找并显示完整命令行
pkill -9 -f app.jar                 # 按完整命令行匹配并强制结束
~~~

### 2.4 STAT 列常见取值

| 取值 | 含义 |
|---|---|
| R | 运行中或就绪 |
| S | 可中断睡眠，等待事件，最常见 |
| D | 不可中断睡眠，通常在等待磁盘 I/O |
| T | 已暂停，例如被 Ctrl+Z 挂起 |
| Z | 僵尸进程，已退出但父进程还没回收 |
| I | 空闲的内核线程 |

附加标记：s 表示会话首进程，l 表示多线程，+ 表示位于前台进程组。

## 3. kill：关闭进程

kill 的作用是向进程发送信号，进程收到信号之后如何反应，由信号本身和程序自己决定。

~~~bash
kill PID       # 请求进程正常退出
kill -9 PID    # 强制结束无响应进程
~~~

优先使用普通 kill，让程序自行清理资源。

### 3.1 常见信号

| 信号 | 编号 | 含义 |
|---|---|---|
| SIGTERM | 15 | kill 的默认信号，通知进程优雅退出，程序可以捕获并做收尾 |
| SIGKILL | 9 | 强制杀死进程，无法被忽略或捕获 |
| SIGHUP | 1 | 挂断信号，常用于让服务重读配置文件 |
| SIGINT | 2 | 中断信号，相当于在终端按 Ctrl+C |
| SIGSTOP | 19 | 暂停进程，无法被忽略 |
| SIGCONT | 18 | 让暂停的进程继续运行 |

~~~bash
kill -15 ${PID}    # 优雅退出，等价于 kill PID
kill -9 ${PID}     # 强制杀死
kill -1 ${PID}     # 让服务重读配置
kill -STOP ${PID}  # 暂停
kill -CONT ${PID}  # 继续
~~~

### 3.2 该用哪个信号

- 先发 15，让进程有机会保存数据、关闭连接、释放锁，数据库和中间件尤其要这样关。
- 只有进程卡死、完全不理 15 时才用 9；9 会让进程来不及写盘和清理临时文件。
- 发完信号进程仍在，先看 STAT：Z 表示它已经退出、只等父进程回收；D 表示卡在不可中断的 I/O 上，这时连 9 也杀不掉，只能等 I/O 返回或重启主机。

## 4. top：实时查看状态

top 是实时刷新工具，默认每 3 秒更新一次，能同时看到平均负载、内存和各个进程的资源占用。

~~~bash
top            # 默认每 3 秒刷新一次，按 d 或 s 可改刷新间隔
~~~

按 q 或 Ctrl+C 退出。常见交互键：P 按 CPU 排序，M 按内存排序，k 输入 PID 结束进程，1 展开 CPU 核心。

### 4.1 常用交互按键

| 按键 | 含义 |
|---|---|
| q | 退出 top |
| P | 按 CPU 占用排序 |
| M | 按内存占用排序 |
| T | 按运行时间排序 |
| k | 输入 PID 后结束指定进程 |
| 1 | 展开显示每个 CPU 核心的占用 |
| h | 显示帮助 |

### 4.2 进程列表字段

| 字段 | 含义 |
|---|---|
| PID / USER | 进程 ID / 所属用户 |
| PR / NI | 优先级 / nice 值 |
| VIRT / RES / SHR | 虚拟、物理、共享内存 |
| S | S 休眠、R 运行、Z 僵尸、I 空闲 |
| %CPU / %MEM | CPU / 内存占用率 |
| TIME+ | 累计 CPU 时间 |

### 4.3 顶部信息怎么读

| 信息 | 含义 |
|---|---|
| load average | 三个数值分别表示过去 1 分钟、5 分钟、15 分钟的平均负载 |
| %Cpu(s) | us 用户态占用、sy 内核态占用、id 空闲比例、wa 等待 I/O 的比例 |
| KiB Mem | total 总内存、free 完全空闲、used 已使用、buff/cache 缓冲与页缓存 |
| KiB Swap | 交换分区总量与已用量，用量越大说明物理内存越紧张 |

### 4.4 uptime 与 load average

~~~bash
uptime
~~~

uptime 输出的末尾就是 load average 的三个数值。判断负载是否偏高要和 CPU 核心数比较：4 核机器上 load 长期大于 4 才算过载，8 核机器上 load 为 4 只能算中等；如果负载主要由 wa 贡献，说明瓶颈在磁盘而不是 CPU。

## 5. df、iostat、sar

### 5.1 df：磁盘空间

~~~bash
df -h  # 用人性化单位显示空间
~~~

### 5.2 iostat：CPU 与磁盘 I/O

~~~bash
iostat
iostat -x 2 3  # 每 2 秒刷新，共 3 次详细统计
~~~

重点指标：rKB/s、wKB/s 是读写速率，await 是平均等待时间，avgqu-sz 是平均队列长度，%util 是设备利用率。

### 5.3 sar：网络统计

~~~bash
sar -n DEV 3 2  # 每 3 秒采样一次，共 2 次
~~~

| 字段 | 含义 |
|---|---|
| IFACE | 网卡接口 |
| rxpck/s、txpck/s | 每秒收、发数据包数 |
| rxKB/s、txKB/s | 每秒收、发数据量 |
| rxcmp/s、txcmp/s | 每秒收、发压缩包数 |
| rxmcst/s | 每秒接收多播包数 |

## 6. 本篇知识点总结

1. 进程有 PID，父子进程通过 PPID 关联。
2. ps -ef 配合 grep 可筛选进程。
3. kill 请求退出，kill -9 强制结束。
4. top 实时观察 CPU、内存和进程。
5. df 看空间，iostat 看 I/O，sar 看网络。
