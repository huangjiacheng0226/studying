# 六、文本处理三剑客

> grep 找行、sed 改行、awk 分列，三条命令配合管道，就能覆盖日常大部分日志与配置文件处理。

## 1. 学习目标与前置知识

读完本篇应能：

1. 用 grep 按关键字和正则筛选行，并理解它的退出码含义。
2. 用 sed 打印、删除、替换文本，知道 `-i` 原地修改前要先备份。
3. 用 awk 按列统计，写出求和、求平均、去重计数的单行命令。
4. 把三者与管道组合，解决“日志里访问量最高的 10 个 IP”这类问题。

前置知识：[04-Linux基础命令](04-Linux基础命令.md) 的管道、重定向与 grep 初步用法，[13-Shell脚本与定时任务](13-Shell脚本与定时任务.md) 的退出码约定。

## 2. 三者的定位

三个命令都从标准输入读数据、把结果写到标准输出，所以能靠管道串起来；区别在于处理单位不同：grep 以行为单位筛，sed 以行为单位改，awk 以列为单位算。

| 命令 | 处理单位 | 一句话定位 | 典型场景 |
| --- | --- | --- | --- |
| grep | 行 | 找出符合条件的行 | 在日志里找 ERROR |
| sed | 行 | 按地址修改文本 | 批量替换配置项、取第 10 到 20 行 |
| awk | 列 | 按字段计算和统计 | 求耗时平均值、统计访问量前几名 |

退出码约定对筛选类命令都适用：grep 找到匹配返回 0，没找到返回 1，用法出错返回 2，所以可以写 `grep -q "ERROR" app.log || echo "没有错误"`。

## 3. grep：按行筛选

### 3.1 概念与选项

grep 逐行读入文本，把匹配成功的整行打印出来。关键字里带空格或特殊符号时要用引号包住。

| 选项 | 作用 | 示例 |
| --- | --- | --- |
| -i | 忽略大小写 | grep -i "error" app.log |
| -v | 反向筛选，输出不匹配的行 | grep -v "^#" nginx.conf |
| -n | 显示行号 | grep -n "timeout" nginx.conf |
| -r | 递归搜索目录 | grep -rn "8080" /usr/local/app |
| -c | 只输出匹配行数 | grep -c "ERROR" app.log |
| -E | 使用扩展正则，等价于 egrep | grep -E "^[0-9]{4}-[0-9]{2}" app.log |
| -q | 静默模式，只用退出码 | grep -q "ERROR" app.log |

### 3.2 基本正则元字符

| 元字符 | 含义 | 示例 |
| --- | --- | --- |
| ^ | 行首 | ^# 匹配注释行 |
| $ | 行尾 | ;$ 匹配以分号结尾的行 |
| . | 任意一个字符 | 80. 匹配 800、808 |
| * | 前一个字符重复 0 次或多次 | ab* 匹配 a、ab、abb |
| [] | 字符集合，任选其一 | [0-9] 匹配一个数字 |
| \ | 转义，还原特殊字符的字面量 | \. 匹配真正的点号 |

```bash
grep -n "ERROR" /var/log/nginx/error.log     # 带行号看错误
grep -c "ERROR" /var/log/nginx/error.log     # 只关心数量
grep -v "^#" /etc/nginx/nginx.conf           # 去掉注释行看有效配置
grep -rn "DB_PASSWORD" /usr/local/app/       # 在目录里递归搜索
grep -E "500|502" /var/log/nginx/error.log   # -E 支持扩展正则
```

```text
$ grep -c "ERROR" /var/log/nginx/error.log
12

$ grep -E "500|502" /var/log/nginx/error.log
2024-05-01 10:02:11 [error] 502 upstream error
2024-05-01 10:03:40 [error] 500 internal error
```

## 4. sed：按行编辑

### 4.1 工作方式

sed 一行一行处理文本：把当前行读进“模式空间”，按脚本执行命令，默认把结果打印到标准输出，然后处理下一行。脚本的写法是“地址 + 命令”，不写地址就作用于每一行。

| 常用命令 | 作用 |
| --- | --- |
| p | 打印当前行，通常与 -n 搭配 |
| d | 删除当前行，即不输出 |
| s/旧/新/ | 替换每行第一处匹配 |
| s/旧/新/g | 替换每行所有匹配 |
| i | 在匹配行之前插入文本 |
| a | 在匹配行之后追加文本 |

### 4.2 打印与删除

`-n` 表示关闭默认输出，只有脚本里显式 `p` 的行才会打印，这样才能做到“只要第 2 到 5 行”。

```bash
sed -n '2,5p' app.log            # 打印第 2 到 5 行
sed -n '$p' app.log              # 只打印最后一行
sed -n '/ERROR/p' app.log        # 打印含 ERROR 的行，接近 grep
sed '2,5d' app.log               # 删除第 2 到 5 行，输出其余内容
sed '/^$/d' app.log              # 删掉空行
sed '1d' app.log                 # 去掉表头
```

### 4.3 替换

替换是最常用的功能：`s///g` 里的 g 表示整行所有匹配都替换，不加 g 只替换第一处；分隔符可以换成 `#`、`|` 等，处理路径时更省事。

```bash
sed 's/8080/9090/' app.conf                  # 每行只替换第一处
sed 's/8080/9090/g' app.conf                 # 每行替换全部
sed -n 's/^listen/#listen/p' nginx.conf      # 注释掉 listen 行
sed 's#/usr/local/app#/opt/app#g' app.conf   # 换分隔符处理路径
```

### 4.4 原地修改与备份

`-i` 会把结果直接写回原文件，改错就没有回头路，所以修改前先备份是最重要的习惯：`-i.bak` 会自动生成同名 `.bak` 文件。

```bash
sed -i.bak 's/8080/9090/g' app.conf    # 修改前自动备份为 app.conf.bak
sed -i 's/8080/9090/g' app.conf        # 直接改原文件，没有备份
```

### 4.5 常用场景速查

| 需求 | 命令 |
| --- | --- |
| 打印第 10 到 20 行 | sed -n '10,20p' file |
| 删除含某关键字的行 | sed '/关键字/d' file |
| 把 tab 换成两个空格 | sed 's/\t/  /g' file |
| 给每行行首加井号 | sed 's/^/#/' file |
| 只在含 server 的行做替换 | sed '/server/s/80/8080/g' file |

## 5. awk：按列处理

### 5.1 工作方式

awk 把每一行按分隔符切成若干列，再对列做判断和计算。默认分隔符是空格或 tab，`$1` 是第一列，`$0` 是整行；脚本写法是 `模式 { 动作 }`，省略模式表示每行都执行动作。

| 写法 | 含义 |
| --- | --- |
| -F ',' | 指定分隔符，例：awk -F ',' '{print $1}' |
| $0 | 整行内容 |
| $1 $2 ... $n | 第 1、2、n 列 |
| NF | 当前行的列数，$NF 是最后一列 |
| NR | 当前行号，也就是记录序号 |
| BEGIN { } | 处理第一行之前执行，常用来打印表头 |
| END { } | 全部处理完后执行，常用来汇总 |

```bash
awk -F ',' '{print $1}' users.csv        # csv 取第一列
awk '{print $1, $NF}' app.log            # 取第一列和最后一列
awk 'NR==2 {print $2}' app.log           # 只看第 2 行的第 2 列
awk 'NF>5 {print NR": "$0}' app.log      # 列数大于 5 的行，附行号
```

### 5.2 条件过滤

模式部分就是条件，用法接近 grep，但可以按列比较：

```bash
awk '$9 > 1000 {print $1, $9}' app.log    # 第 9 列大于 1000
awk '$7 == "ERROR" {print $0}' app.log    # 某列等于固定值
awk '/ERROR/ {print $1}' app.log          # 模式也支持正则
awk '$1 != "127.0.0.1"' app.log           # 排除本机请求
```

### 5.3 统计：求和、求平均、去重计数

```bash
awk '{sum += $9} END {print sum}' app.log                        # 求和
awk '{sum += $9} END {print sum/NR}' app.log                     # 求平均
awk '{print $7}' app.log | sort | uniq -c | sort -rn             # 去重计数
awk '{count[$1]++} END {for (i in count) print count[i], i}' app.log
```

第一行把第 9 列不断累加到自定义变量 sum，处理完所有行后打印总和；第二行用总和除以行数得到平均值，NR 在处理结束后就是总行数；第三行的思路是“先切列、再排序、再去重计数、最后按次数倒序”；第四行不借助管道，直接用 awk 数组完成去重计数，`count[$1]++` 表示以第一列作为下标累加出现次数。

```text
$ awk '{sum += $9} END {print sum/NR}' app.log
245.38

$ awk '{print $1}' access.log | sort | uniq -c | sort -rn | head -n 3
   1042 192.168.1.101
    318 192.168.1.102
     97 10.0.0.5
```

## 6. 三者对比与组合

| 需求 | 首选 | 说明 |
| --- | --- | --- |
| 找关键字所在行 | grep | 最简单，支持 -r 递归目录 |
| 取一段行、批量替换 | sed | 面向行，适合改配置 |
| 按列求和、统计 | awk | 面向字段，能写变量和数组 |
| 既要筛行又要统计 | 管道组合 | grep 筛行，awk 统计 |

组合的关键是每一步只做一件事，用管道把行流交给下一个命令：

```mermaid
flowchart LR
    A[原始日志] --> B[grep 筛出目标行]
    B --> C[sed 取需要的行段]
    C --> D[awk 切列与统计]
    D --> E[sort 排序]
    E --> F[head 取前 N 条]
```

统计 nginx 日志里访问量最高的 10 个 IP（日志第一列是 IP）：

```bash
awk '{print $1}' /var/log/nginx/access.log | sort | uniq -c | sort -rn | head -n 10
grep "ERROR" /var/log/nginx/access.log | awk '{print $1}' | sort | uniq -c | sort -rn
```

第一条命令依次做五件事：取第一列、排序、去重计数、按次数倒序、取前 10 条；第二条先筛出 ERROR 行再统计来源 IP，用来定位错误集中在哪台客户端。

## 7. 小白易错点

下面按 grep、sed、awk、通用四组列出高频坑，每条都给出能自己动手验证的对照写法。

1. 模式没加引号，被 shell 先展开：`grep *.log app.log` 里的 `*.log` 会先被 shell 展开成当前目录的文件名，`grep [0-9] app.log` 在目录里存在单个数字命名的文件时也会被当成文件名参数。模式一律用单引号包住，交给 grep 自己解释。

    ~~~bash
    grep [0-9] app.log      # [0-9] 可能先被 shell 当成文件名去匹配
    grep '[0-9]' app.log    # 单引号保护，模式原样交给 grep
    ~~~

2. 把 `.` 当成普通的点号：正则里 `.` 匹配任意一个字符，`grep '1.1' app.log` 连 `1a1`、`101` 都算命中，要匹配真正的点号必须写 `\.`。

    ~~~bash
    grep '1.1' app.log      # 1.1、1a1、1x1 全部命中
    grep '1\.1' app.log     # 只命中字面量 1.1
    ~~~

3. 不知道 grep 读二进制文件只提示、不输出内容：对 jar 包或二进制日志直接 grep，屏幕上只有一行 `Binary file app.jar matches`，看不到匹配内容；加 `-a` 才按文本输出，只想要文件名用 `-l`。

    ~~~bash
    grep "ERROR" app.jar        # 输出 Binary file app.jar matches
    grep -a "ERROR" app.jar     # 强制按文本打印匹配行
    ~~~

4. 以为 `grep -c` 数的是出现次数：它数的是匹配的行数，同一行里出现三次也只算 1 行。要统计真正的出现次数用 `grep -o` 配合 `wc -l`。

5. `grep -r` 不限定范围，在根目录或大目录里递归：会扫到 `/proc`、`/sys` 这类特殊目录，既慢又刷屏，还夹着一堆权限报错。把范围收窄到业务目录，必要时用 `--exclude-dir` 排除系统目录。

6. 以为 sed 会改原文件：不带 `-i` 时 sed 只把处理结果写到标准输出，原文件一个字都没变，于是有人反复执行同一条替换命令却始终看不到文件变化。

    ~~~bash
    sed 's/8080/9090/g' app.conf            # 只打印，app.conf 不变
    sed -i.bak 's/8080/9090/g' app.conf     # 原地修改，同时留下 .bak 备份
    ~~~

7. `-i` 的写法在 GNU 与 macOS 上不同：GNU sed 是 `sed -i '脚本' 文件`，macOS 自带的 BSD sed 要求 `-i` 后面紧跟一个后缀参数，写 `sed -i '' '脚本' 文件` 才表示不备份；照抄 GNU 写法会把脚本当成后缀吞掉。

    ~~~bash
    sed -i 's/8080/9090/' app.conf       # GNU sed 的写法
    sed -i '' 's/8080/9090/' app.conf    # macOS 自带 sed，空后缀表示不备份
    ~~~

8. 说不清替换里的 `&` 与 `\1` 是什么：`&` 代表整个匹配到的内容，`\1` 代表第一个括号分组。想给关键字整体加壳用 `&`，想调换两段顺序用分组；要输出字面量 `&` 得写 `\&`。

    ~~~bash
    sed 's/8080/[&]/' app.conf               # 8080 变成 [8080]
    sed -E 's/(.*)=(.*)/\2=\1/' app.conf     # key=value 换成 value=key
    ~~~

9. 基本正则里直接用括号分组：不加 `-E` 时 `(` 与 `)` 只是普通字符，`sed 's/(.*)=(.*)/\1/'` 什么也匹配不到，要么写成 `\(` 与 `\)`，要么加 `-E` 走扩展正则。

    ~~~bash
    sed 's/(.*)=(.*)/\2=\1/' app.conf      # 没有 \，括号是字面量，匹配失败
    sed -E 's/(.*)=(.*)/\2=\1/' app.conf   # -E 之后括号才是分组
    ~~~

10. 替换内容里有斜杠却不换分隔符：处理路径、日期、URL 时，`s/.../.../` 的分隔符会和内容里的 `/` 打架，报 `unknown option to 's'`，把分隔符换成 `#` 或 `|` 即可。

    ~~~bash
    sed 's//usr/local/app//opt/app/g' app.conf    # 报 unknown option to 's'
    sed 's#/usr/local/app#/opt/app#g' app.conf    # 换 # 当分隔符后正常
    ~~~

11. 用 `p` 打印行时忘了 `-n`：sed 默认先把每行原样输出一遍，再加 `p` 就变成“全文加重复的目标行”，看起来像内容被写了两份。

12. 以为 awk 按逗号或制表符分列：默认分隔符是连续的空白字符（空格与 tab），一列内容里含空格时列号会整体错位，必须用 `-F` 指定真正的分隔符。

13. 把 awk 里的 `$1` 当成 shell 的 `$1`：awk 程序要用单引号包住，否则 shell 先把 `$1` 展开成脚本或函数的第一个参数，awk 收到的已经是别的内容了。

14. 分不清 NR 与 FNR：NR 是已经处理过的总行数（多个文件累加），FNR 是当前文件内的行数。多文件汇总统计用 NR，想跳过每个文件的表头用 FNR。

    ~~~bash
    awk 'NR==1 {print}' a.txt b.txt     # 只打印最先处理的第一个文件的首行
    awk 'FNR==1 {print}' a.txt b.txt    # 两个文件的首行都打印
    ~~~

15. `ps -ef | grep 关键字` 把 grep 自己也算了进去：grep 进程的命令行里含有这个关键字，所以结果里总多一条，用 `grep -c` 计数也会偏大。加 `grep -v grep` 排除自身，或直接改用 `pgrep -f 关键字`。

16. 以为管道的退出码是自己关心的那条命令的退出码：`cmd1 | cmd2` 的 `$?` 只看得到 cmd2 的结果，cmd1 失败会被悄悄掩盖，脚本里的判断因此失效。要查管道中某一段用 `${PIPESTATUS[0]}`，或在脚本开头打开 `set -o pipefail`。
