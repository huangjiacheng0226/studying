## 1.权限一览表

具体权限的作用详见[官方文档](https://dev.mysql.com/doc/refman/8.0/en/privileges-provided.html)。下面两张表是从官方文档原样搬过来的英文清单，先看这张常用权限对照表，就能应付绝大多数场景：

| 权限 | 作用 | 典型授予对象 |
| --- | --- | --- |
| `SELECT` / `INSERT` / `UPDATE` / `DELETE` | 对表的查询、新增、修改、删除 | 业务应用账号 |
| `CREATE` / `DROP` / `ALTER` | 建表、删表、改表结构 | 开发或迁移账号 |
| `INDEX` | 创建和删除索引 | 开发账号 |
| `EXECUTE` | 执行存储过程与函数 | 业务应用账号 |
| `CREATE VIEW` / `SHOW VIEW` | 创建视图、查看视图定义 | 报表账号 |
| `CREATE ROUTINE` / `ALTER ROUTINE` | 创建和修改存储过程、函数 | 开发账号 |
| `TRIGGER` | 创建和删除触发器 | 开发账号 |
| `PROCESS` | 查看其他会话正在执行的语句 | DBA 排查用 |
| `RELOAD` | 执行 `FLUSH` 类操作 | DBA 运维用 |
| `REPLICATION CLIENT` / `REPLICATION SLAVE` | 查看复制状态、作为从库拉取 binlog | 复制账号 |
| `SHUTDOWN` | 关闭数据库实例 | DBA 运维用 |
| `SUPER` | 8.0 之前的高权限集合，8.0 起被拆分 | 尽量避免直接授予 |
| `USAGE` | 没有任何实际权限，只表示"能登录" | 新建账号时的默认值 |

授权与回收的基本写法：

```SQL
-- 建一个只能用业务库的账号；主机名决定允许从哪些机器登录
CREATE USER 'app'@'192.168.1.%' IDENTIFIED BY '${DB_PASSWORD}';

-- 按库授予最小权限，不要图省事写 ALL ON *.*
GRANT SELECT, INSERT, UPDATE, DELETE ON tlias.* TO 'app'@'192.168.1.%';

-- 让权限立即生效
FLUSH PRIVILEGES;

-- 查看某个账号的权限
SHOW GRANTS FOR 'app'@'192.168.1.%';

-- 回收权限
REVOKE DELETE ON tlias.* FROM 'app'@'192.168.1.%';
```

两个容易踩的点：一是主机名写 `%` 等于允许任意来源登录，生产环境要收窄到具体网段或固定 IP；二是 `USAGE` 看起来像权限，其实只是"可以登录"的占位，不能拿它当任何一种操作权限。

## 2.小技巧

### 最小权限与角色

日常账号应遵循最小权限原则：只授予完成工作所需的库、表或操作权限，不要把 `ALL PRIVILEGES` 直接授予应用账号。MySQL 8.0 还支持角色，可以把权限集中授予角色，再将角色分配给用户：

```SQL
CREATE ROLE 'report_reader';
GRANT SELECT ON reporting.* TO 'report_reader';
CREATE USER 'report_user'@'localhost' IDENTIFIED BY '<your-password>';
GRANT 'report_reader' TO 'report_user'@'localhost';
SET DEFAULT ROLE 'report_reader' TO 'report_user'@'localhost';
```

更多权限说明见 [MySQL 8.0 权限列表](https://dev.mysql.com/doc/refman/8.0/en/privileges-provided.html)。

1. 在SQL语句之后加上`\G`会将结果的表格形式转换成行文本形式

2. 查看Mysql数据库占用空间：

```SQL
SELECT table_schema "Database Name"
     , SUM(data_length + index_length) / (1024 * 1024) "Database Size in MB"
FROM information_schema.TABLES
GROUP BY table_schema;
```
3. MySQL 8.0 默认认证插件是 `caching_sha2_password`，旧版客户端可能报 `Authentication plugin 'caching_sha2_password' cannot be loaded`。两种处理方式：优先升级客户端驱动；确实无法升级时，把该账号改成旧插件作过渡——`ALTER USER 'app'@'%' IDENTIFIED WITH mysql_native_password BY '${DB_PASSWORD}';`。要注意 `mysql_native_password` 自 8.0.34 起已被标记弃用，只适合短期兼容，不要作为长期方案。

4. 查看每张表用的存储引擎和大致数据量，判断该不该动某个库：

```SQL
SELECT table_name, engine, table_rows,
       ROUND(data_length / 1024 / 1024, 2) AS data_mb,
       ROUND(index_length / 1024 / 1024, 2) AS index_mb
FROM information_schema.tables
WHERE table_schema = 'tlias'
ORDER BY data_length DESC;
```

`table_rows` 是估算值，InnoDB 下不精确，但用来找"哪张表最大"足够了。

5. 排查字符集和排序规则问题（乱码、比较不区分大小写多数出在这里）：

```SQL
SHOW VARIABLES LIKE 'character_set%';
SHOW VARIABLES LIKE 'collation%';
SHOW FULL COLUMNS FROM emp;   -- 看单张表每列的字符集
```

6. 查看当前有哪些连接、有没有语句卡住：

```SQL
SHOW FULL PROCESSLIST;        -- 谁在跑、跑了多久、什么状态
SHOW ENGINE INNODB STATUS;    -- 最近一次死锁、锁等待、事务情况
```

`SHOW ENGINE INNODB STATUS` 的输出很长，在命令行里通常用 `\G` 结尾让它按行展开，方便阅读：

```SQL
SHOW ENGINE INNODB STATUS\G
```

## 小练习

为一个只读报表用户设计最小权限集合，并说明为什么不应直接授予 `ALL PRIVILEGES`。
